# Rust `guilds` service — port spec (Phase 4)

> Historical: the migration completed on `rework/rust-backend`; see `rust-go-removal-plan.md`.

The fourth Rust service in the Go→Rust backend migration (after identity, players, servers). New axum 0.8 + sqlx 0.8 binary at `apps/rust/services/guilds`, **default PORT 8093**, talking to the **same Postgres** as the Go backend. **NO schema changes / NO migrations** — Go's `EnsureSchema()` owns every table; the guilds service only reads/writes existing tables. JSON responses must match the Go handlers **byte-for-byte** (frontend + bot TS types depend on them). `cargo clippy --all-targets` must stay warning-clean; parameterized queries only.

## Scope (what this service owns)

The guild-domain surface still on Go. Everything else in `/guilds/*` is already ported: tracked-servers + online-summary + tracked-server-log-events → **servers**; game-bans + guild steam-discord links + nickname-targets + track-group **analytics** → **players**.

| Cluster | Routes | Auth |
|---|---|---|
| Guild settings | GET/PUT `/guilds/{g}/settings` | bot-JWT |
| User-guilds | POST `/user-guilds`, POST `/user-guilds/leave`, GET `/discord/{d}/guilds` | bot-JWT |
| Bot-guilds | POST `/bot-guilds/{upsert,leave,reconcile}` | bot-JWT |
| Bot-user-installs | POST `/bot-user-installs/seen` | bot-JWT |
| Wipe-reacts | GET active/list, POST create, GET/PUT/DELETE `{msg}`, POST/DELETE reactions | bot-JWT |
| Wipe-react schedules | GET list, POST create, GET/PUT/DELETE `{id}` | bot-JWT |
| Schedule-post queue | POST claim, POST `{id}/complete`, POST `{id}/release` | bot-JWT |
| Background scheduler | `wipereactscheduler` poller (enqueues due posts) | worker |
| Track-groups | CRUD, members add/remove, online-state, notifications/claim | bot-JWT |
| Admin guild list/detail | GET `/api/app/admin/guilds`, GET `/api/app/admin/guilds/{g}` | app-secret + session + `guilds.read` |

All bot-JWT routes are under `/api/internal/bot/setup` and gated by the shared bot service JWT (`rustlens-botjwt`, `BOT_SERVICE_JWT_SECRET`). The two admin routes use `rustlens-httpauth::require_admin` (app-secret + `X-RustLens-Session` + permission).

## Global conventions (all routes)

- **byte-for-byte JSON**: Go builds most responses from `map[string]any`, which `encoding/json` emits with **lexicographically sorted keys** + a **trailing `\n`** (from `json.Encoder`) + **HTML escaping** (`<`→`<`, `>`→`>`, `&`→`&`). The Rust port must reproduce all three (use `BTreeMap`/sorted serialization, append `\n`, HTML-escape). Struct-based responses (admin routes) marshal in struct field order.
- `snowflakePattern = ^\d{17,20}$`; `steamIDPattern = ^\d{17}$`; body cap `1<<20` (1 MB) → decode failure = `400 {"error":"invalid request body"}`. `writeError` = `{"error":msg}`.
- `time.Time` in a `map` → **RFC3339Nano** (Z, trailing-zero fraction trimmed). Two documented exceptions to watch: `UpsertBotGuild.membersSyncedAt` = plain RFC3339 (seconds), and admin `guild.installedAt/leftAt` = RFC3339 seconds (pre-formatted strings) while the other admin list timestamps are RFC3339Nano.
- Empty lists always serialize as `[]`, never `null` (Go `make([]…,0)`). JSONB string arrays decode jsonb `null`→`null`, `[]`→`[]` (wipe-react id lists preserve this nil-vs-empty distinction end-to-end).

## Design decisions

- **D-G1 — service + port.** New `apps/rust/services/guilds`, `GuildsConfig` in `rustlens-config`, default PORT **8093**. Env mirrors servers (POSTGRES_URL, REDIS_URL, BOT_SERVICE_JWT_SECRET + iss/aud, APP_SESSION_SECRET, APP_API_INTERNAL_SECRET). *(follows the established pattern; no user input needed)*
- **D-G2 — store in `rustlens-db`.** New query modules: `guild_settings`, `user_guilds`, `bot_guilds`, `bot_user_installs`, `wipe_reacts`, `wipe_react_schedules`, `wipe_react_schedule_posts`, `track_groups`, `admin_guilds`. Consistent with identity/players/servers. *(no user input needed)*
- **D-G3 — scheduler worker locking. ✅ RESOLVED: Redis-locked** (SetNX cadence lock like the servers poller). Go runs the `wipereactscheduler` poller **lock-free** across replicas (idempotency from `UNIQUE(schedule_id,wipe_unix) DO NOTHING` + the `last_posted_for_unix >= wipe_unix` guard). Options: (a) replicate the Go Redis SetNX cadence lock we used for the servers poller (avoids N replicas doing redundant enqueue work — consistent with the servers slice); (b) run it truly lock-free like Go (simplest, still correct). Recommend **(a) Redis-locked**, matching the servers decision.
- **D-G4 — admin guild routes home. ✅ RESOLVED: include in guilds (slice G-E).** `GET /api/app/admin/guilds` + `/{guildID}` are app-secret+session+`guilds.read` gated (not bot-JWT) and read across many domains. Options: (a) include them in the guilds service as the final slice (completes the guild admin surface; they're guild-domain reads); (b) defer them (they were deferred in the identity phase). Recommend **(a) include**.
- **D-G5 — cross-domain reads (read-only, accepted).** Track-group online-state reads `player_states`/`steam_accounts`/`steam_account_cache`/`bm_profile_cache`/`guild_steam_discord_links`; the admin detail reads ~12 tables across servers/players/linking/usage domains. Shared DB, read-only — consistent with prior phases; the guilds service just needs read helpers.
- **D-G6 — chrono/chrono-tz for the scheduler.** The `computeNext*` timezone math (weekly/biweekly/monthly + first-Thursday-19:00-Europe/London force wipe) must mirror Go's `time.Date`/`AddDate`/`LoadLocation` semantics exactly, including DST-gap/ambiguous resolution (Go normalizes forward / deterministic). Use `chrono_tz::Tz` + calendar-day stepping.

- **G-A — skeleton + settings + sync.** `GuildsConfig`, service skeleton (health, bot-JWT gate, main), + guild settings (GET/PUT), user-guilds (create/leave/list), bot-guilds (upsert/leave/reconcile), bot-user-installs (seen). All simple CRUD/upsert; good foundation.

Bot-JWT-gated `/api/internal/bot/setup`. Handlers handlers.go / bot_guilds_handlers.go / bot_user_installs_handlers.go. writeJSON trailing `\n` + HTML-escape. time.Time → RFC3339Nano (Z) EXCEPT membersSyncedAt (plain RFC3339 secs). NO 404 anywhere in this group.

### A) GUILD SETTINGS

ErrNoRows → synthetic zero-value {all "" , limited=false, guildId set}, NO insert, 200 (not 404). err→500 `failed to fetch guild settings`. Resp keys: guildId, wipeReactLogChannelId, linkingLogChannelId, trackedServerLogChannelId, trackedUsersCategoryId, adminRoleId, alertRoleId (strings), limited (bool). created/updated_at NOT exposed.
- PUT `/guilds/{guildID}/settings` UpdateGuildSettings: req all optional pointers: wipeReactLogChannelId, linkingLogChannelId, trackedServerLogChannelId, trackedUsersCategoryId, adminRoleId, alertRoleId (*string, snowflake-validated in that order via validateSnowflakeOptionalField: nil OK, "" OK, else must match else 400 `<field> must be a valid Discord snowflake`), limited (*bool, NOT validated). decode fail→400 `invalid request body`. Store (3 statements, no tx): `INSERT INTO guild_settings (guild_id) VALUES ($1) ON CONFLICT (guild_id) DO NOTHING`; then `UPDATE guild_settings SET wipe_react_log_channel_id=COALESCE($2,...), linking_log_channel_id=COALESCE($3,...), tracked_server_log_channel_id=COALESCE($4,...), tracked_users_category_id=COALESCE($5,...), admin_role_id=COALESCE($6,...), alert_role_id=COALESCE($7,...), limited=COALESCE($8,limited), updated_at=NOW() WHERE guild_id=$1`; then re-Get. **Semantics: omitted key (nil→NULL)=preserve; ""(non-nil empty)=clear to ''; snowflake=set.** err→500 `failed to save guild settings`. 200 same shape. PUT ALWAYS creates row if absent.
- **NOTE `limited` is in DDL+struct+SQL+JSON but MISSING from CLAUDE.md guild_settings doc. Include it.**

### C) BOT-GUILDS
- POST `/bot-guilds/upsert` UpsertBotGuild: req {guildId(req snowflake), name(opt, NOT validated), iconHash/bannerHash/ownerDiscordId/ownerUsername/ownerGlobalName/ownerAvatarHash (*string, NOT validated even ownerDiscordId), approximateMemberCount(*int32), members([]string each snowflake, cap 1000=maxMembersPerUpsertBatch), membersSyncComplete(bool)}. Does NOT re-activate.**

## Wipe-reacts

Bot-internal, JWT-gated (`/api/internal/bot/setup`, middlewares bridgeAPIKeyPerms → requireBotRouteScope → botJWTMiddleware; effective auth = bot service JWT bearer, `BOT_SERVICE_JWT_SECRET`). Handlers `apps/backend/internal/http/handlers.go`; store `internal/store/wipe_reacts.go`; table `wipe_reacts`.

### Shared conventions
- `snowflakePattern = ^\d{17,20}$`. `validateGuildID`: empty→400 `guildID is required`; bad→400 `guildID must be a valid Discord snowflake`. `validateSnowflakePathParam(name)`: empty→400 `<name> is required`; bad→400 `<name> must be a valid Discord snowflake` (uses exact chi param name e.g. `messageID`,`userID`). `validateSnowflakeValue(v)` = non-empty && matches (body fields).
- Body limit `maxRequestBodyBytes = 1<<20`. Decode err→400 `invalid request body`. Unknown JSON fields ignored.
- `writeError` → `{"error":msg}`. `writeJSON`: sets content-type, encodes with **trailing \n** and **Go HTML-escaping ON** (`<`→`<`,`>`→`>`,`&`→`&`). Rust must replicate trailing newline + HTML escape + **lexicographically sorted map keys**.
- Sentinel `ErrWipeReactNotFound` ("wipe react not found") → 404 everywhere. Other store errs → 500 route-specific msg.
- NO cross-domain access; only `wipe_reacts` table. Reaction routes use tx + FOR UPDATE; others autocommit.

### Request struct `wipeReactPayload` (POST create + PUT update)
channelId, messageId, creatorId, name, description, timeZone (all string); scheduledUnix int64; askLateReason, askDeclinedReason bool; acceptedUserIds, declinedUserIds, lateUserIds []string; embedTimestamp string.
`validateWipeReactPayload(requireMessageID=true for both POST/PUT)` order (first failure→400): 1 channelId snowflake; 2 messageId snowflake (if required); 3 creatorId snowflake; 4 name!="" (`name is required`); 5 timeZone!="" (`timeZone is required`); 6 scheduledUnix>0 (`scheduledUnix must be greater than zero`); 7 embedTimestamp!="" (`embedTimestamp is required`); 8 total ids ≤10000 (`reaction user id lists exceed maximum allowed size`); 9 every id snowflake (`reaction user ids must be valid Discord snowflakes`). description/askLateReason/askDeclinedReason never validated; timeZone/embedTimestamp only non-empty (not parsed).

### Response `wipeReactToMap` (sorted keys on wire)
Keys: guildId, channelId, messageId, creatorId, name, description, timeZone (strings); scheduledUnix (bare int); askLateReason, askDeclinedReason (bool); acceptedUserIds, declinedUserIds, lateUserIds (array-of-string **or null** — nil slice→null, non-nil→[...]/[]); embedTimestamp (string).
Wire order (sorted): acceptedUserIds, askDeclinedReason, askLateReason, channelId, creatorId, declinedUserIds, description, embedTimestamp, guildId, lateUserIds, messageId, name, scheduledUnix, timeZone. List responses: `{"items":[...]}` always non-nil (`[]` when empty).

### Routes
- GET `/wipe-reacts/active` `ListActiveWipeReacts`: `SELECT <14 cols> FROM wipe_reacts WHERE guild_id=$1 AND scheduled_unix>$2 ORDER BY scheduled_unix DESC, message_id DESC` ($2=now Unix). 200 items. err→500 `failed to list active wipe reacts`.
- GET `/wipe-reacts` `ListWipeReacts`: same but `WHERE guild_id=$1` (no time filter). err→500 `failed to list wipe reacts`. (chi matches `/active` and `/wipe-reacts` before `/{messageID}`.)
- POST `/wipe-reacts` `CreateWipeReact`: validate(require msgID). INSERT (message_id,guild_id,channel_id,creator_id,name,description,time_zone,scheduled_unix,ask_late_reason,ask_declined_reason,accepted_user_ids::jsonb,declined_user_ids::jsonb,late_user_ids::jsonb,embed_timestamp). No ON CONFLICT (dup PK→500). **Returns 200 (not 201), echoes the INPUT record (no DB re-read)** → id arrays reflect exactly what client sent (null stays null, [] stays []). err→500 `failed to create wipe react`.
- GET `/wipe-reacts/{messageID}` `GetWipeReact`: `SELECT ... WHERE guild_id=$1 AND message_id=$2`; ErrNoRows→ErrWipeReactNotFound→404. 200 wipeReactToMap (arrays normalized via decodeStringSlice: jsonb []→[], jsonb null→null). other→500 `failed to fetch wipe react`.
- PUT `/wipe-reacts/{messageID}` `UpdateWipeReact`: forces payload.MessageID=path before validate. `UPDATE wipe_reacts SET name,description,time_zone,scheduled_unix,ask_late_reason,ask_declined_reason,embed_timestamp,updated_at=NOW() WHERE guild_id=$1 AND message_id=$2` — **does NOT write channel_id/creator_id/reaction arrays** (immutable here, but channelId/creatorId still must validate). RowsAffected 0→404. On success re-reads via GetWipeReact, returns fresh. other→500 `failed to update wipe react`.
- DELETE `/wipe-reacts/{messageID}` `DeleteWipeReact`: `DELETE ... WHERE guild_id=$1 AND message_id=$2`; RowsAffected 0→404. 200 `{"status":"deleted"}`. other→500 `failed to delete wipe react`.
- POST `/wipe-reacts/{messageID}/reactions` `SetWipeReactReaction`: body `{userId,type}`. userId snowflake else 400 `userId must be a valid Discord snowflake`; type∈{accepted,declined,late} else 400 `type must be one of accepted, declined, or late`. TX+FOR UPDATE. Resp 200 `{changed:bool, wipeReact:{...}, previousType:"accepted"|"declined"|"late"|null}` (sorted: changed, previousType, wipeReact). previousType = user's reaction before (accepted→declined→late precedence, first match) or null. changed = prev==nil || *prev!=type. If changed: remove from all 3 lists then append to target (deduped), write all 3 arrays + updated_at=NOW(); arrays built with make(...,0) so never null when changed. If !changed: no write, still commits, returns row as read. 404 / 500 `failed to update wipe react reaction`.
- DELETE `/wipe-reacts/{messageID}/reactions/{userID}` `RemoveWipeReactReaction`: all 3 path params snowflake-validated; **no body read**. TX+FOR UPDATE. Resp 200 `{changed, wipeReact, removedType}` (sorted: changed, removedType, wipeReact). removedType = list removed from or null; changed = removedType!=nil. If found: remove from all 3, write, updated_at=NOW(). 404 / 500 `failed to remove wipe react reaction`.

### Store/SQL helpers
- `scanWipeReact`: cols order guild_id,channel_id,message_id,creator_id,name,description,time_zone,scheduled_unix,ask_late_reason,ask_declined_reason,accepted_user_ids,declined_user_ids,late_user_ids,embed_timestamp. jsonb cols → []byte → decodeStringSlice.
- `decodeStringSlice`: len 0 → non-nil []string{}; else json.Unmarshal → jsonb []→[], jsonb null→nil (emits null). `encodeStringSlice` = json.Marshal (nil→null, empty→[]).
- Reaction tx (Set/Remove): Begin; `SELECT ... FOR UPDATE`; ErrNoRows→NotFound; compute prev/removed + changed; if changed `UPDATE wipe_reacts SET accepted_user_ids=$3::jsonb, declined_user_ids=$4::jsonb, late_user_ids=$5::jsonb, updated_at=NOW() WHERE guild_id=$1 AND message_id=$2` (writes all 3); Commit (even if !changed).
- `ListPastWipeReacts` exists (scheduled_unix<=cutoff LIMIT) but NO route in scope calls it.

### Edge cases
Create=200 echo-input (null/[] preserved end-to-end; Rust must marshal missing/null input → jsonb null, echo raw arrays, decode jsonb null→null). Reaction responses normalize arrays to non-null when changed. PUT ignores channelId/creatorId/arrays in write. scheduledUnix bare int. No 409 on dup create (→500). created_at/updated_at never in responses. embedTimestamp opaque, verbatim.
## Wipe-react schedules + scheduler

Bot-JWT-gated `/api/internal/bot/setup`. Handlers `handlers.go`; store `wipe_react_schedules.go` + `wipe_react_schedule_posts.go`; poller `internal/wipereactscheduler/poller.go`.

### Shared: validateGuildID (snowflake). validateScheduleIDParam: ParseInt base10; err or ≤0 → 400 `scheduleID must be a positive integer` (on complete/release this param is the POST id). Body cap 1MB; decode err→400 `invalid request body`. writeJSON trailing `\n` + **sorted map keys** (byte-for-byte).

### wipeReactSchedulePayload / validate
Fields: days []string; includesForceWipe bool; time string(HH:MM); timeZone string(IANA); repeat string(weekly/biweekly/monthly); postBefore string(1d/2d/3d/4d/1w/2w); name, description string (no validation); askLateReason, askDeclinedReason bool; channelId string (NOT validated); createdBy string (snowflake).
Validate order (first fail→400): 1 each day ∈ {monday..sunday} else `each day must be one of monday, tuesday, wednesday, thursday, friday, saturday, sunday`; 2 timeZone!="" else `timeZone is required` (only emptiness); 3 postBefore ∈ {1d,2d,3d,4d,1w,2w} else `postBefore must be one of 1d, 2d, 3d, 4d, 1w, 2w`; 4 createdBy snowflake else `createdBy must be a valid Discord snowflake`; 5 if !includesForceWipe && len(days)==0 → `days must not be empty when includesForceWipe is false`; 6 if len(days)>0: time ^\d{2}:\d{2}$ else `time must match HH:MM format`, repeat ∈ {weekly,biweekly,monthly} else `repeat must be one of weekly, biweekly, monthly`. Force-wipe-only (days:[]) valid w/ empty time/repeat. nil days → [].

### scheduleMap (sorted keys): askDeclinedReason, askLateReason (bool), channelId, createdBy (string), days ([]string never null), description, guildId (string), id (int64), includesForceWipe (bool), lastPostedForUnix (int64), name, postBefore, repeat, time, timeZone (strings). ### Poller (poller.go, started in main.go, single instance, NO advisory lock — idempotency = UNIQUE(schedule_id,wipe_unix) + last_posted_for_unix guard).
Interval 60s (runs immediately then every 60s). tick: ListAllWipeReactSchedules (all guilds, ORDER BY guild_id ASC, id ASC); nowUnix=Now().Unix(); per schedule: next=computeNextPostTime; skip if nil; skip if now<next.postUnix; skip if LastPostedForUnix>=next.wipeUnix; else EnqueueWipeReactSchedulePost(scheduleID,guildID,channelID,wipeUnix,postUnix). Enqueue = `INSERT INTO wipe_react_schedule_posts (schedule_id,guild_id,channel_id,wipe_unix,post_unix) VALUES (...) ON CONFLICT (schedule_id,wipe_unix) DO NOTHING`. Net: enqueue when postUnix<=now<wipeUnix and last_posted_for_unix<wipeUnix.

**computeNextPostTime(schedule, nowUnix)→{wipeUnix,postUnix} or nil:**
1. postBefore = postBeforeSeconds[postBefore] (1d=86400,2d=172800,3d=259200,4d=345600,1w=604800,2w=1209600); missing→nil.
2. afterUnix = LastPostedForUnix; if <=0 → afterUnix = nowUnix - postBefore - 1 (backdate floor so fresh schedule gets immediate lead time).
3. earliestWipeUnix=0; per day: occ=computeNextWeekdayOccurrence(...); if !=0 keep min.
4. if IncludesForceWipe: fw=computeNextForceWipeOccurrence(afterUnix,nowUnix); if !=0 and smaller (or earliest 0) take it.
5. earliest==0→nil else {wipeUnix:earliest, postUnix:earliest-postBefore}.

**computeNextWeekdayOccurrence(dayName,timeText,tz,repeat,afterUnix,nowUnix)→int64 (0=none):**
targetDay=map (missing→0); loc=LoadLocation(tz) err→0 (invalid/empty tz → no weekday occ); parsedTime=ParseInLocation("15:04",timeText,loc) err→0 (use Hour/Minute); after=Unix(afterUnix).In(loc); startDay=local-midnight of after; minGap = 13*86400 if repeat=="biweekly" else 0. offset 0..62 incl: candidateDay=startDay.AddDate(0,0,offset); skip if weekday!=target; if repeat=="monthly" && candidateDay.Day()>7 skip (first weekday of month, dom 1-7); candidate=Date(y,m,d,hour,min,0,0,loc); candidateUnix; skip if <=afterUnix; skip if <=nowUnix (strictly future); skip if minGap>0 && candidateUnix-afterUnix<minGap; return candidateUnix. else 0.
repeat: weekly=next future; biweekly=next future ≥13d after afterUnix; monthly=first target-weekday of month (dom≤7).

**computeNextForceWipeOccurrence(afterUnix,nowUnix)→int64:** first Thursday of month 19:00 Europe/London (DST-aware). loc=LoadLocation("Europe/London") err→0; after=Unix(afterUnix).In(loc); year,month=after; monthOffset 0..3 (cur+next3): candidateMonth=month+offset (wrap >12, +year); day 1..7: candidate=Date(candYear,candMonth,day,19,0,0,0,loc); if weekday!=Thursday continue; (first Thu) if Unix>afterUnix && Unix>nowUnix return else break inner (next month, ignore later Thursdays same month). else 0.
**Rust: chrono-tz Tz; mirror Go DST resolution (Go Date normalizes gap forward / picks deterministic for ambiguous — use from_local_datetime resolving to Go's choice); AddDate = calendar-day step in tz not 86400s.**
